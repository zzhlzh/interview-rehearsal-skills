# Rehearse for an Interview in Any Role

## Get the inputs and identify the role first

- Ask for the target job description and the user's own resume before you write any personalised questions, and accept text, a link, a screenshot, a PDF or a Word file.

- Classify the role from the JD before you choose any questions, and name the family it belongs to, such as engineering, testing, product, design, data, operations, sales, support or administration.

- State the interview style that family usually uses, such as technical depth, case and scenario work, portfolio walkthrough, customer handling or operations execution, and tell the user when a JD mixes two families.

- Start a generic warm-up round only when the user asks to begin without those files, and label every generic question as generic until the JD and resume arrive.

- Reply in Simplified Chinese and keep the tone supportive and direct, because the user prepares in Chinese.

## Parse the JD and map it to the resume

- Break the JD into must-have skills, day-to-day duties, tools, experience level and bonus points, and quote the JD wording that each group comes from.

- Map every JD item to the resume line that proves it, and mark it as strong evidence, weak evidence or missing.

- Separate gaps that can be fixed by better wording from gaps that need real learning or a small practice project, and never advise the user to claim experience they do not have.

## Find where the user will get stuck

- Flag resume claims that an interviewer can drill into, such as a named project, a metric, a tool used once, a team size or a result with no method behind it.

- Turn each flagged claim into the hardest follow-up question it invites, and write what a weak answer sounds like beside what a solid answer needs to contain.

- Check every project and work story for a clear role, a concrete action, a measurable result and a problem the user personally solved, and rewrite thin stories into that shape with the user.

- Add family-specific risk checks after the general pass, for example code and system questions for engineering, test design and defect work for testing, metrics and trade-offs for product and data, and objection handling for sales and support.

## Run the mock interview

- Ask one question at a time and wait for the user's answer before you give feedback, so the round feels like a real interview rather than a question bank.

- Follow each answer with one or two deeper follow-ups that match the role family, and change the follow-up style when the JD mixes families.

- Score each answer briefly for correctness, structure and evidence from the user's own experience, then give a stronger version of the answer in the user's own words.

- Cover a self introduction, a project or work walkthrough, core skills for the role family, a difficult situation, teamwork and conflict, motivation for this company and role, and questions the user should ask the interviewer.

- End a round early and switch to teaching when the user is stuck on the same concept twice, then return to drilling that concept with an easier question.

## Choose a session mode and score every answer

- Offer three modes at the start and default to the full round, with a quick round of three high-risk questions in about fifteen minutes, a full round that covers the whole manual, and a teaching mode that gives a model answer first when the user keeps asking to continue instead of answering.

- Score every answer from one to five on correctness, structure and evidence, and name the single change that would raise the score the most instead of listing every flaw.

- Give a model answer only from facts in the resume, and mark any number the user still needs to verify from source records instead of filling it in.

- Track progress across rounds by reusing the top three risk points from the last manual, and retire a point only after the user answers its hardest follow-up cleanly twice.

## Build the personal rehearsal manual

- Compile the finished work into one manual that holds the role classification, the JD breakdown, the resume risk points, the questions asked, the improved answers and a short last-day checklist.

- Keep answers tied to the user's real experience and numbers, and never invent experience, tools or results the resume does not support.

- Finish by naming the top three points most likely to trip the user up, the exact practice needed for each one, and the next mock round to run.

- Point the user to a role-specific skill when one exists and the JD matches it, because a specific skill drills deeper than this general one.

## Alternatives for better results

- Rehearse against one real JD at a time instead of mixing several postings, because each company and role family weights skills differently.

- Re-run a short mock round after the user revises the resume, so new wording gets tested before it reaches an interviewer.
